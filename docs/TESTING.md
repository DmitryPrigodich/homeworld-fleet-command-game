# Automated regression runs

Run `Test.cmd` on Windows, or `./scripts/Test.ps1`. The full suite builds Core/Game, runs 56 rule checks, six whole-battle scenarios, seven special-order scenarios, nine interrupt scenarios and seventeen tabletop-foundation scenarios, nine close-combat scenarios and thirteen defense/Barrage scenarios. It drives nine Godot UI checks and starts seven real ENet host/client pairs: PvP, co-op, cards, special orders, Interrupt Attack, post-roll tabletop decisions and defensive fire. Processes have a 45-second timeout. Test games, profiles and saves use isolated directories under `tmp/test-results`; production saves are not overwritten.

For fast checks without Godot: `./scripts/Test.ps1 -CoreOnly`.
For an engine elsewhere: `./scripts/Test.ps1 -Godot 'C:\Tools\Godot_console.exe'` (the .NET build is required).

Results: `tmp/test-results/summary.json`, `scenarios.json`, per-scenario `*.trace.json`, and engine stdout/stderr logs. A nonzero exit code means failure. Traces are written after each command, including rejected commands, so a failed run retains the failing input. The report contains command order, side, seed, round, sequence and a SHA-256 state hash. Run the same JSON specification to reproduce it.

Scenario specifications live in `tests/scenarios/`. Fields are `name`, `map`, `seed`, optional `maxCommands`, `closeContact` and `useSpecialOrders`. The close-contact fixture keeps one original interceptor squadron per side and places them adjacent; no dice or combat statistics are changed. The deterministic test policy prefers legal attacks, otherwise approaches an enemy, otherwise passes. The special-order policy also starts supported cards and advances their pending actions. Card initiative uses zero-card commitments in these long battle runs.

Each battle runs twice: continuously and with save/load after every command. The states must match at every step. Every run must terminate within its command budget, reject commands after completion and preserve prior snapshots. Card runs additionally check deck conservation through validation, private player views, hidden deck/RNG, rejection of opponent-card bids and repeated commitments. A close-contact run requires a decisive victory; longer patrols may end in a round-limit draw.

GitHub Actions runs Core checks and scenarios on each push/PR and uploads scenario traces. Full Godot UI and ENet tests currently run through the Windows script; CI does not claim those engine tests ran.

The seven focused special-order scenarios cover straight movement with mid-order restore, skipping steps, finishing early, preassigned distinct actors, blocked straight paths despite a possible detour, a destroyed attack target, missing Afterburners and invalid saved steps. Each accepted or rejected command is also attempted after serialization of its input snapshot. One destruction fixture deliberately increases attack dice and lowers the target's model count to guarantee the timing case; whole-battle fixtures retain normal combat statistics. Private snapshots and exact one-card/one-Play spending are checked throughout. These sequence tests decline response windows; the whole-battle policy plays Interrupt Attack whenever legal. The Godot check clicks a highlighted destination, saves/loads the pending step and exercises skip/finish buttons; the ENet pair restores the host's on-disk save between the client's two actions.

The nine interrupt scenarios cover an activated responder, no extra Play, once-per-round use and end-of-round discard/reset, mid-path restore, allied pass-through, invalid actors/cards/targets, destroyed basic/formation actors, immediate victory, hidden-hand-independent windows and malformed saves. High armor fixtures preserve actors for continuation checks; destruction fixtures alter dice/models to guarantee the timing case. Every command is replayed after save/load, compared exactly and checked against private views. UI tests fire through a real viewport click, repeat/exit the lesson, verify save isolation, restore mid-move and decline windows. The ENet test reloads the host's on-disk pending window before accepting the remote response and requires `INTERRUPT_NETWORK_RESUMED` in the host log.

The close-combat scenarios cover target/facing rejection without spending, boarding armor/crew/buffs, hulks, return collision after destruction, overrun, fighter sacrifice/crippling, scenario-authorized capture and crew/leader transfers. Defense scenarios exercise support/focus/terrain, fighter casualties, destroyed boarders, ram continuation, current-round boarding locks, crippled weapons, Valor versus Ferocious, powered-drone Evasive, offensive/defensive Barrage, malformed saves and defense inside an interrupt during movement. Each command is replayed after save/load, compared exactly, checked for immutable input and redacted client authority. Some rolls/statistics are deliberately fixed to guarantee a timing case; no guessed published unit data is introduced.

The defense UI check saves and restores both before the defensive roll and after it. Its ENet pair requires `DEFENSE_NETWORK_RESUMED` and `DEFENSE_ROLL_NETWORK_RESUMED` on the host, reduces the incoming missile pool, completes the original order and checks client-private snapshots. Rendered checks can additionally save `tmp/defense-choice.png` and `tmp/close-collision.png`.

# Card practice scope

The separate tabletop development mode (`practice:rules`, `tabletop: true`) implements the foundations listed in RULES_COVERAGE.md. Its dedicated scenarios cover leader budgets and multiple hidden bids, cleanup and correct deck exhaustion, turning and gravity, arcs and weapon target classes, saved post-roll rerolls, rapid/evasive cancellation, armor/focus/buff timing, damage control (including two actors and post-roll distribution), Kushan repair and cosmetic isolation. UI checks exercise the actual bid/attack/reroll/repair/cleanup controls and disk saves. The tabletop ENet test restores a post-roll host save and continues a Valor reroll, with an art pack enabled only on the client. These additions do not mean the full published ruleset or deck is complete.

Open Single player > Card practice, the card guide under Tutorial, or enable the card checkbox when hosting a skirmish. The training deck has 24 instances: eight All Ahead Full, eight Stay in Formation, four Interrupt Attack and four basic-only cards. These counts are a testing distribution, not the published deck composition. Existing instance IDs are retained; IDs 17–20 now have the interrupt effect when played as a reaction. It uses a shared shuffled deck, Hand 2 / Play 1 (faction-only practice), retention of unused cards, replenishment, discard recycling, and an explicit initiative phase. Each player may commit zero or one card for +1 (roll capped at 6); ties consume that attempt's bids and require fresh commitments. Any hand card pays for a Move or Attack. The UI falls back to the first hand card unless one is selected.

Source basis: user-supplied `HWFC_Rulebook_v020LW.pdf`, pp. 10, 12–16, read alongside Errata 1.7. All Ahead Full permits two straight moves; this implementation interprets the second as continuing in the same direction, without reversing. Both straight paths must be clear and respect terrain costs. Stay in Formation preassigns and activates two distinct ready units: first Move → Attack, then Lightning Move → Attack. Lightning Move uses the second ship's Afterburners distance and must end adjacent to the first unit. Actions may be omitted, including the first unit's actions. One card and one Play pay for the entire sequence; round cleanup waits until completion. Saves retain actors, step and straight-move direction.

Interrupt Attack follows the card on p. 14 and interrupt timing on p. 15 of the supplied `HomeworldBG_Rulebook_US_Digital.pdf`, checked visually as well as against the earlier edition. An allied unit, whether activated or ready, attacks only the enemy actor during its Move, Lightning Move or Attack. This spends no Play and does not change activation. Each side may play one Attack interrupt per round; the used card remains face up until round-end discard. An attack pauses before rolling. Movement uses a deterministic cheapest path and offers a pause after each empty hex with a potential responder; allied occupied cells are crossed before pausing. Skipped special actions produce no response window. The currently selected route cannot be redirected after a response. Legacy practice retains simplified movement; tabletop mode implements turning-only moves and class-specific turning.

Implementation limits: prototype movement, facing and attack geometry remain in use; full class-specific arcs/turning are pending. There is no ramming bonus on All Ahead Full (removed by Errata 1.7); tabletop mode implements ramming as a separate attack kind. Other special cards and interrupt types, reinforcement/harvest, CAP, terrain attacks and complete scenario medal objectives remain tracked work. Tabletop mode adds full initiative bidding, cleanup discards, leaders and Valor. Patrol victory still uses prototype elimination/round limits.

Opposing card hands, pending opposing bids, draw-pile order and authoritative RNG are removed from remote snapshots. Played special/interrupt cards, assigned actors, current step and response route are public. Window eligibility uses public geometry and already-played interrupt types, regardless of hidden hands. Co-op shares the host-side hand. Full host saves preserve the deck, pending commitments, order, movement route and response; client views cannot execute authoritative commands. The interrupt protocol signature rejects older binaries.
