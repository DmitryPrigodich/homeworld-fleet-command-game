# Automated regression runs

Run `Test.cmd` on Windows, or `./scripts/Test.ps1`. The full suite builds Core/Game, runs 56 rule checks, five whole-battle scenarios and seven special-order scenarios, drives five Godot UI checks and starts four real ENet host/client pairs: PvP, co-op, cards and special orders. Processes have a 45-second timeout. Test games, profiles and saves use isolated directories under `tmp/test-results`; production saves are not overwritten.

For fast checks without Godot: `./scripts/Test.ps1 -CoreOnly`.
For an engine elsewhere: `./scripts/Test.ps1 -Godot 'C:\Tools\Godot_console.exe'` (the .NET build is required).

Results: `tmp/test-results/summary.json`, `scenarios.json`, per-scenario `*.trace.json`, and engine stdout/stderr logs. A nonzero exit code means failure. Traces are written after each command, including rejected commands, so a failed run retains the failing input. The report contains command order, side, seed, round, sequence and a SHA-256 state hash. Run the same JSON specification to reproduce it.

Scenario specifications live in `tests/scenarios/`. Fields are `name`, `map`, `seed`, optional `maxCommands`, `closeContact` and `useSpecialOrders`. The close-contact fixture keeps one original interceptor squadron per side and places them adjacent; no dice or combat statistics are changed. The deterministic test policy prefers legal attacks, otherwise approaches an enemy, otherwise passes. The special-order policy also starts supported cards and advances their pending actions. Card initiative uses zero-card commitments in these long battle runs.

Each battle runs twice: continuously and with save/load after every command. The states must match at every step. Every run must terminate within its command budget, reject commands after completion and preserve prior snapshots. Card runs additionally check deck conservation through validation, private player views, hidden deck/RNG, rejection of opponent-card bids and repeated commitments. A close-contact run requires a decisive victory; longer patrols may end in a round-limit draw.

GitHub Actions runs Core checks and scenarios on each push/PR and uploads scenario traces. Full Godot UI and ENet tests currently run through the Windows script; CI does not claim those engine tests ran.

The seven focused special-order scenarios cover straight movement with mid-order restore, skipping steps, finishing early, preassigned distinct actors, blocked straight paths despite a possible detour, a destroyed attack target, missing Afterburners and invalid saved steps. Each accepted or rejected command is also attempted after serialization of its input snapshot. One destruction fixture deliberately increases attack dice and lowers the target's model count to guarantee the timing case; whole-battle fixtures retain normal combat statistics. Private snapshots and exact one-card/one-Play spending are checked throughout. The Godot check clicks a highlighted destination, saves/loads the pending step and exercises skip/finish buttons; the ENet pair restores the host's on-disk save between the client's two actions.

# Card practice scope

Open Single player > Card practice, the card guide under Tutorial, or enable the card checkbox when hosting a skirmish. The training deck has 24 instances: eight All Ahead Full, eight Stay in Formation and eight basic-only cards. These counts are a testing distribution, not the published deck composition. It uses a shared shuffled deck, Hand 2 / Play 1 (faction-only practice), retention of unused cards, replenishment, discard recycling, and an explicit initiative phase. Each player may commit zero or one card for +1 (roll capped at 6); ties consume that attempt's bids and require fresh commitments. Any hand card pays for a Move or Attack. The UI falls back to the first hand card unless one is selected.

Source basis: user-supplied `HWFC_Rulebook_v020LW.pdf`, pp. 10, 12–16, read alongside Errata 1.7. All Ahead Full permits two straight moves; this implementation interprets the second as continuing in the same direction, without reversing. Both straight paths must be clear and respect terrain costs. Stay in Formation preassigns and activates two distinct ready units: first Move → Attack, then Lightning Move → Attack. Lightning Move uses the second ship's Afterburners distance and must end adjacent to the first unit. Actions may be omitted, including the first unit's actions. One card and one Play pay for the entire sequence; round cleanup waits until completion. Saves retain actors, step and straight-move direction.

Implementation limits: prototype movement, facing and attack geometry remain in use; full class-specific arcs/turning are pending. There is no ramming bonus on All Ahead Full (removed by Errata 1.7); ramming itself is not implemented. Other special cards, full initiative bidding, optional pre-draw discard, leaders, interrupts, Valor, reinforcement/harvest and complete scenario medal objectives remain tracked work. Patrol victory still uses prototype elimination/round limits.

Opposing card hands, pending opposing bids, draw-pile order and authoritative RNG are removed from remote snapshots. The played special card, assigned actors and current step are public. Co-op shares the host-side hand. Full host saves preserve the complete deck, pending commitments and pending order; client views cannot execute authoritative commands. The special-order protocol signature rejects older card-mode binaries.
